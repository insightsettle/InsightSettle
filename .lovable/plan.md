# Insight — مطابقة PRD وخطة الوصول لمنصة خليجية متينة

## 1) نتيجة المراجعة (مطابقة PRD)

التقييم العام: حوالي 55% من متطلبات P0 منفّذة. الواجهة والرحلة الأساسية موجودة، لكن الأساس المالي (دفتر الأستاذ، عرض سعر الصرف، آلة الحالات، التدقيق) لا يزال أضعف من المطلوب.

### منفّذ ومطابق
- التسجيل (بريد + Google)، الملفات، صفحة التحقق ورفع المستندات مع مراجعة الفريق
- إنشاء الصفقة، رابط الدعوة، القبول / طلب تعديل / الرفض
- التمويل والإفراج وطلب التحكيم، سجل الدفعات، الرسائل المرتبطة بالصفقة (غير قابلة للتعديل)
- الشحن ورقم التتبع، فترة الفحص مع عدّاد، إشعارات داخل التطبيق
- لوحة الإدارة: مؤشرات، كل الصفقات، الأعضاء، المستندات، تغيير الحالة مع سبب، رسوم خاصة
- واجهة عربية/إنجليزية، هوية فاتحة مع لون فيروزي

### منفّذ جزئيًا
- **آلة الحالات**: 7 حالات فقط، والمطلوب: DRAFT، PENDING_SUPPLIER، ACCEPTED، AWAITING_PAYMENT، PAYMENT_PROCESSING، SECURED، SHIPPED، DELIVERED، INSPECTION، COMPLETED، REJECTED، CANCELLED، PARTIAL_SETTLEMENT
- **حالات الدفع والاسترداد**: لا يوجد RELEASE_PENDING / PARTIALLY_REFUNDED / REFUND_APPROVED، ولا ربط للاسترداد بالدفعة الأصلية
- **الرسوم**: شرائح حسب المبلغ فقط؛ لا يوجد حد أدنى/أقصى، رسوم حسب الدولة أو طريقة الدفع، ولا قواعد تسعير شرطية
- **الشحن**: لا يوجد تاريخ الشحن، ولا الوصول المتوقع، ولا حالة "خارج للتوصيل"، ولا مستندات الشحن
- **KYC**: رفع المستندات فقط؛ لا توجد حقول الجنسية/تاريخ الميلاد/رقم الهوية/العنوان، ولا ملف الشركة (السجل التجاري، الرقم الضريبي)، ولا الحالات REQUIRES_REVIEW / SUSPENDED
- **المخاطر**: تحليل بالذكاء الاصطناعي فقط؛ لا توجد قواعد ثابتة (حساب جديد، مبلغ مرتفع، دولة، دفعات فاشلة، تكرار)
- **الإشعارات**: داخل التطبيق فقط؛ البريد والرسائل النصية غير مفعّلة

### غير منفّذ (نواقص حرجة)
- **أسعار الصرف والرسوم محفوظة في المتصفح** وليست في قاعدة البيانات، فلا تنطبق على كل المستخدمين. هذا أخطر نقص.
- **عرض سعر صرف (FX Quote)** مخزّن بمدة 15 دقيقة، مع تسجيل provider_rate / customer_rate / spread، ومنع استخدام عرض منتهٍ (اختبار 6)
- **دفتر أستاذ مزدوج القيد** (مدين/دائن لكل حركة) وحساب صافي أرباح فرق العملة
- **سجل تدقيق** (القيمة القديمة/الجديدة، المستخدم، IP، الوقت) غير قابل للحذف
- **إصدارات الشروط** (نسخة 1، 2، 3…) عند كل تفاوض
- **حقول الصفقة**: الكمية، سعر الوحدة، دولة المورد، دولة التسليم، مسؤولية الشحن، معايير القبول، شروط الاسترداد والإلغاء، والمرفقات
- **الإفراج التلقائي الفعلي**: الموعد محسوب لكنه لا يُنفَّذ، ولا يمكن تعطيله حسب الصفقة
- **نظام نزاعات حقيقي**: أسباب محددة، رفع أدلة، مهلة رد المورد 48 ساعة، مهلة أدلة 72 ساعة، وتسوية جزئية بنسب (قضايا النزاع الحالية تجريبية)
- **الإلغاء** حسب المرحلة (قبل القبول، قبل الشحن، بعد الشحن، أثناء النزاع)
- **إجراءات الإدارة**: تجميد صفقة، طلب مستندات، تقييد أو إيقاف حساب، ملاحظة داخلية
- **الأدوار**: الدعم، المالية، الامتثال، المدير الأعلى (الموجود: مدير/موظف فقط)
- **الأمان**: تحقق ثنائي للإدارة، مفتاح منع الدفع المزدوج (اختبار 5)، حد لعدد الطلبات، استقبال إشعارات مزود الدفع مع التحقق من التوقيع
- **الصفحات العامة**: للمشترين، للموردين، الأعمال، الأمان، الأسئلة الشائعة
- **جانب المورد**: بيانات الحساب البنكي للتسوية (IBAN) وصفحة التسويات

### إضافات موجودة وليست في الملف
- وسيط الذكاء الاصطناعي لحل النزاعات بمهلة 3 أيام، ثم محكّم خارجي برسوم على العميل
- مراجعة المستندات بالذكاء الاصطناعي، وتقييم المخاطر بالذكاء الاصطناعي (الملف يضعها في المرحلة المستقبلية P2)
- تقييم الطرف الآخر، حاسبة رسوم عامة، صفحات الشروط والخصوصية وسياسة النزاعات، ودعم اللغتين
- تبقى جميعها، مع تعليمها بأنها "استشارية" وليست قرارًا ماليًا

## 2) متطلبات الخليج (إضافة على الملف)
- العملات: SAR، AED، BHD، QAR، KWD، OMR (مع دقة 3 خانات لـ BHD/KWD/OMR)
- ضريبة القيمة المضافة على رسوم المنصة حسب الدولة (السعودية 15%، الإمارات 5%، البحرين 10%، عُمان 5%، قطر والكويت 0%)
- فاتورة ضريبية لكل صفقة برقم تسلسلي و QR متوافق مع ZATCA (المرحلة الأولى)
- التحقق من صيغة IBAN الخليجي وأرقام الجوال (+966، +971، +973، +974، +965، +968)
- نص إفصاح: الأموال محفوظة لدى مزوّد مرخّص (SAMA / CBUAE / CBB)، وليس لدى Insight
- حماية البيانات (PDPL): موافقة صريحة عند التسجيل، مدد احتفاظ واضحة، وطلب حذف أو تصدير البيانات

## 3) خطة التنفيذ (على مراحل)

**المرحلة 1 — الأساس المالي**
- نقل أسعار الصرف وقواعد الرسوم وسياسة النزاعات إلى قاعدة البيانات، بحيث تديرها الإدارة
- عروض أسعار صرف بمدة 15 دقيقة، ومنع التمويل بعرض منتهٍ
- دفتر أستاذ مزدوج القيد، ومفتاح لمنع الدفع المزدوج، وسجل تدقيق عام
- آلة حالات كاملة يفرضها الخادم (لا يمكن القفز بين الحالات من المتصفح)

**المرحلة 2 — الصفقة والتفاوض**
- الحقول الإضافية للصفقة، والمرفقات، وإصدارات الشروط مع المقارنة
- قواعد الإلغاء، والرفض من المورد مع استرداد تلقائي
- الإفراج التلقائي المجدول، مع خيار تعطيله لكل صفقة

**المرحلة 3 — النزاعات والاسترداد**
- جدول نزاعات حقيقي مع الأسباب والأدلة والمهل القابلة للضبط
- قرار: إفراج كامل أو استرداد كامل أو تسوية بنسب، مع تجميد الأموال تلقائيًا
- حالات الاسترداد مرتبطة بالدفعة الأصلية

**المرحلة 4 — الهوية والامتثال والأدوار**
- حقول KYC للأفراد والشركات، والحالات الست
- أدوار الدعم والمالية والامتثال والمدير الأعلى، وصلاحيات كل دور
- محرك مخاطر بقواعد ثابتة + تنبيهات AML، وتجميد وتقييد وإيقاف الحسابات
- تحقق ثنائي إلزامي لحسابات الإدارة

**المرحلة 5 — الخليج والواجهة**
- العملات الست، ضريبة القيمة المضافة، الفاتورة الضريبية PDF مع QR
- IBAN للتسوية، ولوحتا المشتري والمورد بالأقسام المطلوبة في الملف
- الصفحات العامة الناقصة، وموافقة PDPL

**معلّق على قرارك**
- مزوّد الدفع المرخّص (مثل Moyasar أو HyperPay أو Tap أو Checkout.com): البنية ستكون جاهزة للربط
- إشعارات البريد والرسائل النصية: تحتاج نطاق إرسال موثّق ومزوّد رسائل نصية

## Technical notes
- New tables: fx_rates, fee_rules, platform_settings, fx_quotes, ledger_entries, audit_logs, deal_term_versions, deal_attachments, disputes, dispute_evidence, business_profiles, payout_accounts, risk_flags, tax_invoices; app_role gains support, finance, compliance, super_admin.
- Status transitions move to server functions with an allowed-transition map; the direct party UPDATE policy on deals is narrowed to non-financial fields.
- Audit rows are written by triggers on deals, deal_transactions, kyc_documents, user_roles, profiles; no UPDATE/DELETE policies.
- Idempotency: unique (deal_id, kind, idempotency_key) on deal_transactions.
- Auto-release and SLA deadlines run from a scheduled job calling a signed /api/public route.
- Money stays numeric (not float); currency minor units table for 2 vs 3 decimals.
- Admin MFA via the auth TOTP factor, enforced in the console gate (aal2).
